        Definition

        A word RAM is a random access machine whose cells hold words: natural numbers below 2w2 ^ w2w, for a word length www that is a parameter of the model. It has a memory of 2w2 ^ w2w cells, addressed by number, and a distinguished accumulator register. Input arrives on a read-only input tape and output is written on a write-only output tape. A program is a finite sequence of instructions, executed in order unless a jump instruction changes the program counter. Each instruction reads the next input number into a cell, writes a number to the output, loads a value into the accumulator, stores the accumulator into memory — directly or at an address held in a memory cell — combines the accumulator with an operand by addition, subtraction, multiplication, division, bitwise conjunction, disjunction or exclusive or, or a shift, jumps unconditionally or on the accumulator being zero or positive, or halts. An operand is either a literal, the contents of a memory cell, or the contents of the cell whose address is the contents of a memory cell.

        All arithmetic is arithmetic on words: every value the machine produces is taken modulo 2w2 ^ w2w, and every address is taken modulo 2w2 ^ w2w. Subtraction is the exception a machine on unsigned words needs, and is truncated at zero rather than wrapping. Division is integer division, with x/0=0x / 0 = 0x/0=0.

        The machine starts with all memory cells zero, the whole input word on the input tape and the output tape empty; it halts having written the output word. The running time is the number of instructions executed, each costing one time unit.

        35# Formalization notes
        36
        37This is the machine the modern analysis of algorithms is stated on. The
        38unbounded-number RAM of Aho, Hopcroft and Ullman (*The Design and
        39Analysis of Computer Algorithms*, §1.2) and of Cook and Reckhow is
        40honest under unit cost only if its arithmetic is weak, because unit-cost
        41operations on numbers of unbounded length are a form of parallelism. The
        42literature's answer, standard since Fredman and Willard's fusion trees
        43and surveyed by Hagerup (*Sorting and searching on the word RAM*), is to
        44bound the numbers instead of the instruction set: cells hold `w`-bit
        45words, `w` is large enough to address the input — `w ≥ log n`, here
        46always written as an explicit inequality against `2 ^ w` at the point of
        47use — and a word operation costs one time unit because it is one machine
        48instruction on a real machine. Multiplication, division, bitwise
        49operations and shifts are then unproblematic, and this is what makes the
        50model the one in which the results of the algorithms literature are
        51actually stated. The instruction skeleton is still that of Aho, Hopcroft
        52and Ullman: an accumulator, direct and indirect addressing, tapes, and
        53jumps against zero.
        54
        55Truncation is definitional and follows a single rule, applied
        56everywhere and with no exceptions: **every value the machine produces is
        57reduced modulo `2 ^ w` at the point of production, and every address is
        58reduced modulo `2 ^ w` at the point of use.** Values are produced into
        59the accumulator (`load` and every arithmetic instruction), into memory
        60(`store`, `storeInd`, and the number `read` takes off the input tape)
        61and onto the output tape (`write`); addresses are used by `Op.mem` and
        62`Op.ind` when reading and by `setCell` when writing. A literal operand
        63is not reduced where it is written down — that would be a third rule —
        64but the value it produces is, so an oversized literal is never
        65observable except through a word, and for `add`, `mul` and the bitwise
        66instructions this comes to exactly the same thing as reducing the
        67literal. It differs only for the instructions that are not arithmetic
        68modulo `2 ^ w` — truncated subtraction, division and the shifts, whose
        69operands are used as written: an oversized subtrahend empties the
        70accumulator, as does a shift by `w` or more, and division by a number
        71too large to be a word yields zero. Only a program's own literals can be
        72oversized in the first place, since every value it can read out of
        73memory is a word. Two consequences make the rule worth its uniformity:
        74the accumulator and every cell the machine can reach hold words, by
        75construction rather than by an invariant to be proved; and the memory,
        76although indexed by all of `ℕ`, is touched only at the residues below
        77`2 ^ w`, so it is exactly the canonical `2 ^ w`-cell store. On words,
        78truncated subtraction, division, the bitwise operations and the right
        79shift cannot leave the words, so for those instructions the reduction
        80does nothing; it is written anyway, because a rule without exceptions is
        81easier to review than a case distinction.
        82
        83Subtraction is natural-number monus, not subtraction in the ring of
        84residues. The accumulator-and-jump architecture tests `a > b` by
        85subtracting and jumping on a positive accumulator, which is exactly why
        86Aho, Hopcroft and Ullman give their machine signed integers; on an
        87unsigned carrier, truncation at zero is the same load-bearing choice,
        88and without it no comparison would survive. Nothing is lost by it:
        89ring subtraction is `add` of the two's complement, that is `xor` with
        90the all-ones word, `add 1`, `add`, at constant cost once the all-ones
        91word is in a cell, and the two machines therefore simulate each other
        92with constant overhead, so no statement about the model can depend on
        93the choice.
        94
        95Two familiar operations are omitted because a program derives them at
        96constant cost. The remainder of `a` by `b` is `a - b * (a / b)`: save
        97`a`, divide by `b`, multiply by `b`, subtract from the saved `a` — exact
        98because `b * (a / b) ≤ a` never wraps. Bitwise negation is `xor` with
        99the all-ones word `2 ^ w - 1`, which a program obtains once, in `O(w)`
        100steps, by doubling a register from `1` until it wraps to zero and
        101summing the values it passed through. Counting those iterations gives
        102`w` itself, which is why the model needs no instruction reporting the
        103word length: the machine can measure it. Programs are therefore uniform
        104in `w` in the strong sense — one program, all word lengths — and the
        105statements built on this model quantify accordingly.
        106
        107`read` reduces the number it takes off the input tape modulo `2 ^ w`,
        108like every other value. The alternative — halting, or refusing to run —
        109would make the machine partial in the input rather than in its own
        110control flow. The machine stays total and honesty about inputs whose
        111entries do not fit into a word lives on the statement side, in the set
        112of admissible inputs a claim quantifies over, where the rest of the
        113input's well-formedness already lives.
        114
        115Time is the machine's own step count, one unit per instruction, and it
        116is now honest for multiplication precisely because the factors are
        117words. There is no space measure: it would be a further definition over
        118`run`, and space is in any case bounded by the `2 ^ w` cells the machine
        119can address. Randomness is deliberately absent as well; a randomized
        120program is a deterministic program that consumes a word list of random
        121numbers, which is definable downstream over this same machine, with no
        122change to the model.
        123
        124The input and output tapes are the ones of the cited source. They are
        125what makes the machine's memory start out empty, and hence what lets a
        126program address it by fixed cell numbers; an input laid out in memory
        127instead would begin at a cell number depending on the input length. A
        128program that wants random access to its input copies it into memory
        129first, at a cost of one instruction per number, so this is a constraint
        130only on algorithms that would read less than their whole input.
        131
        132Reading and writing are total: an out-of-range program counter halts the
        133machine, as does a read from an exhausted input tape, and every memory
        134cell holds a number, so no error states are needed. `Instr.effect` is
        135the whole of the instruction semantics and `step` adds only the fetch,
        136returning `none` exactly when the machine has halted, so the semantics
        137is deterministic and total by construction. `run w p t` is `t`-fold
        138application of `step`, and it is `none` as soon as the machine halts,
        139which is what makes "halts after exactly `t` steps" in `RunsTo` a
        140statement about the *number of instructions executed*: the time measure
        141is intrinsic to the machine and is not an annotation carried alongside
        142the program. `RunsTo` constrains the output tape and nothing else:
        143memory is scratch space and is left unconstrained on halting.

        211/-- A machine state: the program counter, the accumulator, the contents
        212of every memory cell, the part of the input tape not yet read, and the
        213output tape written so far. -/
        214structure State where
        215 /-- The number of the instruction to be executed next. -/
        216 pc : ℕ
        217 /-- The accumulator. -/
        218 acc : ℕ
        219 /-- The contents of the memory cells; only the cells with number below
        220 `2 ^ w` are ever addressed. -/
        221 mem : ℕ → ℕ
        222 /-- The numbers still to be read from the input tape. -/
        223 inp : List ℕ
        224 /-- The numbers written to the output tape so far. -/
        225 out : List ℕ

        227/-- The value of an operand in a memory, at word length `w`: every
        228address is taken modulo `2 ^ w` before the cell it names is read. -/
        229def Op.value (w : ℕ) : Op → (ℕ → ℕ) → ℕ
        230 | lit n, _ => n
        231 | mem a, m => m (a % 2 ^ w)
        232 | ind a, m => m (m (a % 2 ^ w) % 2 ^ w)
        233
        234/-- The memory `m` with cell `a` set to `v`, at word length `w`: the
        235address and the value written are both taken modulo `2 ^ w`. -/
        236def setCell (w : ℕ) (m : ℕ → ℕ) (a v : ℕ) : ℕ → ℕ :=
        237 fun b => if b = a % 2 ^ w then v % 2 ^ w else m b
        238
        239/-- The effect of one instruction on the state at word length `w`, or
        240`none` if it halts the machine, which a `halt` instruction and a read
        241from an exhausted input tape do. Every value produced is reduced modulo
        242`2 ^ w` and every address used is reduced modulo `2 ^ w`. -/
        243def Instr.effect (w : ℕ) : Instr → State → Option State
        244 | read a, s =>
        245 s.inp.head?.map fun v =>
        246 { s with pc := s.pc + 1, mem := setCell w s.mem a v, inp := s.inp.tail }
        247 | write o, s =>
        248 some { s with pc := s.pc + 1, out := s.out ++ [o.value w s.mem % 2 ^ w] }
        249 | load o, s => some { s with pc := s.pc + 1, acc := o.value w s.mem % 2 ^ w }
        250 | store a, s => some { s with pc := s.pc + 1, mem := setCell w s.mem a s.acc }
        251 | storeInd a, s =>
        252 some { s with pc := s.pc + 1, mem := setCell w s.mem (s.mem (a % 2 ^ w)) s.acc }
        253 | add o, s => some { s with pc := s.pc + 1, acc := (s.acc + o.value w s.mem) % 2 ^ w }
        254 | sub o, s => some { s with pc := s.pc + 1, acc := (s.acc - o.value w s.mem) % 2 ^ w }
        255 | mul o, s => some { s with pc := s.pc + 1, acc := (s.acc * o.value w s.mem) % 2 ^ w }
        256 | div o, s => some { s with pc := s.pc + 1, acc := (s.acc / o.value w s.mem) % 2 ^ w }
        257 | and o, s => some { s with pc := s.pc + 1, acc := Nat.land s.acc (o.value w s.mem) % 2 ^ w }
        258 | or o, s => some { s with pc := s.pc + 1, acc := Nat.lor s.acc (o.value w s.mem) % 2 ^ w }
        259 | xor o, s => some { s with pc := s.pc + 1, acc := Nat.xor s.acc (o.value w s.mem) % 2 ^ w }
        260 | shiftl o, s =>
        261 some { s with pc := s.pc + 1, acc := s.acc * 2 ^ o.value w s.mem % 2 ^ w }
        262 | shiftr o, s =>
        263 some { s with pc := s.pc + 1, acc := s.acc / 2 ^ o.value w s.mem % 2 ^ w }
        264 | jump l, s => some { s with pc := l }
        265 | jzero l, s => some { s with pc := if s.acc = 0 then l else s.pc + 1 }
        266 | jgtz l, s => some { s with pc := if 0 < s.acc then l else s.pc + 1 }
        267 | halt, _ => none
        268
        269/-- One step of the machine at word length `w`: fetch the instruction
        270the program counter points at and execute it. The result is `none` if
        271the machine has halted, which also happens when the program counter has
        272run past the program. -/
        273def step (w : ℕ) (p : Program) (s : State) : Option State :=
        274 p[s.pc]?.bind fun i => i.effect w s
        275
        276/-- The state after `t` steps at word length `w`, or `none` if the
        277machine halts before executing `t` instructions. -/
        278def run (w : ℕ) (p : Program) : ℕ → State → Option State
        279 | 0, s => some s
        280 | t + 1, s => (step w p s).bind (run w p t)
        281
        282/-- The initial state on input `x`: program counter and accumulator
        283zero, all memory cells zero, the input word on the input tape, the
        284output tape empty. -/
        285def initState (x : List ℕ) : State where
        286 pc := 0
        287 acc := 0
        288 mem := fun _ => 0
        289 inp := x
        290 out := []
        291
        292/-- Started on input `x` at word length `w`, the machine executes
        293exactly `t` instructions and then halts, having written the word `y` to
        294its output tape. -/
        295def RunsTo (w : ℕ) (p : Program) (x y : List ℕ) (t : ℕ) : Prop :=
        296 ∃ s : State, run w p t (initState x) = some s ∧ step w p s = none ∧ s.out = y
